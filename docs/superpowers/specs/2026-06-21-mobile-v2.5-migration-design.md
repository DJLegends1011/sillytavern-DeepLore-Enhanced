# Mobile v2.5 Migration Design

**Date:** 2026-06-21

**Status:** Approved for implementation planning

## Context

The `codex-mobile-hybrid-shell` branch contains the mobile shell developed against the pre-v2.5 codebase. It is 62 commits ahead of and 113 commits behind `origin/staging`, with merge base `88f4567`. Its first unique commit is PR #30's Obsidian deep-link fix (`0cd9b27`), which was closed without merge and independently superseded by v2.5 commit `218b8af`.

The branch's mobile-only delta after excluding PR #30 is 26 files with 11,561 insertions and 2 deletions. A dry-run merge reports nine textual conflicts, but the more important incompatibility is semantic: v2.5 removed the transient `lastInjectionSources`, `lastPipelineTrace`, `onPipelineTraceUpdated`, and `setLastInjectionSources` APIs in favor of `VerdictStore`.

## Goal

Rebuild `codex-mobile-hybrid-shell` on the current `origin/staging` baseline, preserving the verified mobile experience while adopting v2.5 runtime, lifecycle, styling, and localization contracts.

## Non-Goals

- Do not carry PR #30's commit, helper functions, regression tests, or conflict resolutions into the rebuilt branch.
- Do not change the maintainer's backend behavior beyond the narrow adapters required by the mobile UI.
- Do not translate mobile copy into the six non-English locales. English keys are canonical and existing locale fallback supplies English until the maintainer translates them.
- Do not redesign the established mobile overlay, FAB, Browse, Injection, Librarian, Filters, or Tools experiences.
- Do not preserve the old branch's 62-commit topology. The rebuilt branch will use focused migration commits.

## Branch and History Strategy

1. Fetch and verify `origin/staging` and `origin/codex-mobile-hybrid-shell`.
2. Create a local safety backup ref at the current mobile head (`ce4a171`).
3. Build the replacement from `origin/staging`, not by merging the divergent histories.
4. Transplant only the mobile modules, mobile tests, mobile CSS, setup-wizard mobile behavior, relevant documentation, and minimal integration changes.
5. Exclude `0cd9b27` and all PR #30-only changes.
6. After verification, move `codex-mobile-hybrid-shell` to the rebuilt commit and push using `--force-with-lease`.

`--force-with-lease` is mandatory so the push fails if the remote mobile branch changes after the migration begins.

## Architecture

### Mobile presentation layer

The seven existing modules under `src/mobile/` remain the mobile presentation layer:

- `mobile-shell.js`: lifecycle, event routing, and top-level composition.
- `mobile-overlay.js`: overlay chrome, tab bar, quick actions, and error presentation.
- `mobile-fab.js`: floating action button placement, visibility, drag, and viewport behavior.
- `mobile-state.js`: normalized local UI state.
- `mobile-browse.js`: pure Browse filtering, sorting, option, and row derivation.
- `mobile-injection.js`: pure Injection filtering, timer extraction, and row derivation.
- `mobile-stats.js`: pure compact status-stat derivation.

Rendering helpers remain pure where they are pure today. SillyTavern and DeepLore runtime dependencies enter through the shell's provider interface rather than being imported into those helpers.

### v2.5 runtime adapter

`index.js` will provide the mobile shell with the current-chat Verdict boundary:

- `getCurrentVerdict()` returns the current Verdict for the active chat.
- `onVerdictChanged(callback)` subscribes the shell to committed Verdict changes.

The adapter will reuse v2.5's existing `VerdictStore` imports and active-chat binding. It will not recreate pipeline state or introduce a second mobile-specific store.

The shell may continue importing stable state such as vault index, indexing status, circuit status, lore gaps, pin/block notifications, cooldowns, decay state, and pipeline phase. Removed source/trace globals must not be reintroduced.

### Lifecycle integration

The v2.5 extension lifecycle remains authoritative:

- Create the mobile shell only after i18n initialization and drawer creation have completed.
- Destroy the mobile shell from the same teardown path that destroys the drawer and other extension UI.
- Register mobile subscriptions once and return unsubscribe functions for teardown.
- Preserve v2.5 initialization latches, chat-switch handling, and settings lifecycle behavior.

## Data Flow

The current Verdict is the sole source of per-generation mobile Injection data:

- `verdict.injectedSources` supplies injected rows, count badges, and Copy Titles.
- `verdict.trace` supplies rejected/filter details and diagnostic context.
- `onVerdictChanged` triggers a mobile rerender after a Verdict commit.
- Existing state observers continue to trigger rerenders for indexing, pipeline phase, circuit state, AI stats, lore gaps, and pin/block changes.

The mobile snapshot builder accepts explicit source overrides for tests and otherwise reads the provider-backed Verdict. A missing Verdict produces the existing empty state without falling back to removed globals.

### Reroll behavior

The mobile reroll quick action will:

1. Clear the AI search cache.
2. Clear the persisted `deeplore_injection_log` metadata when available.
3. Preserve the current committed Verdict until the next generation commits its replacement.
4. Report metadata-write failures without treating the already-cleared cache as a total failure.

It will not call `setLastInjectionSources`, clear the Verdict ring, or delete historical Verdict rows.

### Obsidian behavior

Mobile Obsidian actions will use v2.5's `openObsidianUri`. The generic `openExternalProtocol` and `buildObsidianAnchorHtml` helpers from PR #30 will not be transplanted.

## Styling and Responsive Behavior

The mobile stylesheet will be ported onto v2.5's current `style.css` rather than replacing or preferring the stale branch copy.

- Preserve mobile-specific selectors and behavior under `body.dle-mobile-ui-active`.
- Reconcile colors, spacing, borders, motion, forced-colors behavior, and reduced-motion behavior with current v2.5 tokens.
- Preserve the glass overlay fallback for browsers without backdrop-filter support.
- Preserve FAB collision avoidance for SillyTavern drawers, extension menus, custom bottom navigation, Character Library surfaces, missing chat input, and keyboard-driven visual viewport changes.
- Keep desktop drawer behavior unchanged when mobile mode is inactive.

## Localization

Every user-facing mobile string will use v2.5 i18n helpers. New canonical keys will be added only to `locales/dle.en.json`.

The existing locale loader merges English into active locale dictionaries, so untranslated mobile keys render in English for non-English users. No placeholder keys or duplicate English values will be added to the other six locale files.

Internal comments and test descriptions may remain English and do not require locale keys.

## Error Handling

- Runtime command, refresh, clipboard, settings, metadata, and Browse-action failures remain visible in the mobile error card or toast surface.
- Missing Verdict data is an empty state, not an exception.
- Failed Obsidian launch attempts use the existing v2.5 helper behavior and mobile-visible feedback where the caller can detect failure.
- Subscription and DOM teardown operations are idempotent so hot reload and extension teardown do not leave duplicate listeners or orphaned mobile roots.
- A failed force-push lease check stops publication and requires a fresh remote comparison; it must not be bypassed with plain `--force`.

## Testing Strategy

### Test-driven migration

Before runtime changes, add failing tests that prove:

- Mobile snapshots read `injectedSources` and `trace` from a provided Verdict.
- Verdict updates trigger rerender subscriptions.
- Copy Titles uses Verdict sources.
- Reroll clears the AI cache and injection log without clearing the Verdict.
- Empty or cross-chat Verdict state does not leak stale Injection content.
- English i18n keys resolve for all mobile controls and messages.

Then implement the smallest runtime changes required to pass those tests.

### Automated verification

Run, in this order:

1. Focused mobile tests.
2. Import verification.
3. Regression tests.
4. Full `test:all` suite with mobile tests included.
5. ESLint.

The current pre-migration baseline is 450 passing mobile tests. The migrated branch must retain those tests and add coverage for the v2.5 adapter behavior.

### Browser verification

Verify the SillyTavern mobile UI at representative narrow-phone, wide-phone, and touch-tablet widths. Exercise:

- FAB visibility, drag, persistence, and keyboard resizing.
- Overlay open, close, swipe dismissal, tab transitions, and reduced motion.
- Injection rows, filters, Copy Titles, Browse navigation, and empty states.
- Browse search, filters, cards, pin, block, copy, and Obsidian actions.
- Quick actions, settings opening, refresh errors, and mobile-mode controls.
- Switching between mobile and desktop layouts without duplicate UI or listeners.

### Android verification

Use emulator-driven QA against the local SillyTavern target. Capture screenshots and logs while exercising touch drag, swipe dismissal, keyboard resizing, tab switching, and collisions with SillyTavern surfaces.

## Commit Structure

The rebuilt branch will use focused commits in this order:

1. Restore pure mobile modules and their existing focused tests.
2. Add the v2.5 Verdict adapter and lifecycle integration using TDD.
3. Port mobile CSS and setup-wizard responsive behavior.
4. Add English i18n keys and migrate mobile rendering to them.
5. Restore and update mobile documentation.
6. Apply fixes found by full browser and Android verification.

Each commit must leave its focused tests passing. The final force-push occurs only after the complete verification matrix passes.

## Success Criteria

- `codex-mobile-hybrid-shell` is based on the verified `origin/staging` commit used at migration start.
- PR #30 commit `0cd9b27` is absent from the rebuilt branch ancestry.
- No removed pipeline source/trace global is imported or reintroduced.
- Mobile Injection state is Verdict-backed and chat-correct.
- The established mobile UX works across browser and Android verification.
- Desktop behavior remains unchanged with mobile mode inactive.
- New mobile copy is represented by canonical English i18n keys with fallback for other locales.
- Automated tests, import verification, full suite, and lint pass.
- The remote branch is updated only through `git push --force-with-lease`.
